# Never let the client assert its own correctness

**What broke:** `recordAnswer(questionId, correct, topic)` took `correct` and `topic` straight from the client and wrote them to `answer_log`/`question_progress` unchecked. A Server Action is a public POST endpoint regardless of what the UI sends — nothing stopped a direct caller from posting `recordAnswer("x", true, "Variations")` in a loop and manufacturing a perfect record. No leaderboard existed yet to make this worth exploiting, but the PRD names leaderboards as a follow-on, and the hole would have been sitting there waiting.

**Why it wasn't a trivial fix:** the obvious-looking fix — "look up the question by id and compare the client's chosen index to `correctIndex`" — doesn't work here, because `session/page.tsx` randomizes each question's option *order* per session load (`randomizeOptionOrder()`, to stop "always pick the first option" gaming). The index the client picked is a display-order index, not the canonical bank's index, and the server has no record of which way a given session's coin flip landed.

**The fix:** `recordAnswer` now takes the selected option's *text*, not an index or a boolean. The server looks up the question by id from the canonical (non-randomized) bank and compares the submitted text against `options[correctIndex]` — text is stable regardless of display order, so this works correctly with the randomization instead of needing to know about it. Topic is read from the same canonical record, never from the client. See `recordAnswer` in `src/app/actions.ts` and `getQuestionById` in `src/lib/db.ts`.

**The reusable lesson:** when a Server Action's job is "record whether the user got X right," the server has to independently derive "right" from data it controls — never accept it as an input. If a client-side transformation (randomized order, shuffled options, client-only state) makes the naive version of that check awkward, that's a sign to key the comparison off something stable (content, not position/index) rather than a sign to skip the check.

# A color token tuned for text isn't automatically safe as a fill

**What broke:** while building the Site Diary redesign, the correct-answer option highlight used `bg-mint text-[var(--accent-text)]` - the same "solid fill + fixed dark text" pattern already established as safe for the accent/gold color. It isn't: computed contrast of the fixed dark text (`#241D14`) against the light-mode mint fill (`#2F5D52`) is ~2.2:1, well under WCAG's 4.5:1 floor. The same pattern was about to ship in three more places (`Button3D`'s `coral`/`mint` tones, a progress-page "Practice" link, a flags-page reason badge) before being caught and fixed across all of them in one pass.

**Why the working accent pattern didn't generalize:** `--gold`/`--accent` was deliberately designed to stay similarly light in *both* themes, which is exactly what makes a single fixed dark text color safe on top of it in either theme. `--mint`/`--coral` were designed for the opposite job - they're "ink" colors meant to be legible *as text on paper*, so they're deliberately dark in light mode and brightened in dark mode. That's the right design for `text-mint`/`border-coral`/etc., and the wrong shape entirely for "pick one fixed text color that works as a fill in both themes" - in light mode the fill is dark (wants light text), in dark mode the fill is light (wants dark text), so no single fixed color survives both.

**The fix:** for tokens that flip meaningfully in *lightness* (not just hue) between themes, don't try to fill with them and pick a fixed contrasting text color. Either keep the token to border+text-on-paper uses only (as the "APPROVED"/"QUERIED" stamp badges do), or fill with a low-opacity tint of it (`bg-mint/15`, `bg-coral/15`) and pair that with the page's own `var(--ink)` - which already flips correctly between themes - instead of inventing a second fixed color.

**The reusable lesson:** a color pattern that's verified safe for one token isn't safe by analogy for a different token with different design intent - re-derive (or at least re-check) contrast per token, not per pattern. Before reusing a "fill + fixed text" recipe, ask whether the fill color was actually *designed* to stay stable across themes (like an accent) or was designed to flip its own lightness (like an ink/stamp color) - those need opposite treatments.
